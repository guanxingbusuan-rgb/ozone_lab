# ozone_lab 可输入物种全表（111 物种 × 5 通道，V2.4）

> **本表回答**："机制里 111 个物种，**哪些能在哪个输入通道里设**？"
> —— 它是**可选菜单**，不是**必填清单**。
>
> ### ⚠ 选择性输入（核心原则）
>
> **你只填你需要的，不填的自动取零/默认值，程序永远能跑。** 三级实测：
>
> | 输入完整度 | 实测结果 |
> |---|---|
> | **全部配置清空**（IC/排放/BC/沉降 全空文件） | ✅ 可跑，O₃max = 0 ppb（无排放，物理正确） |
> | **极简**（IC 只 3 个 / 排放只 2 个 / 沉降只 2 个 / BC 只 1 个） | ✅ 可跑，O₃max = 11.6 ppb |
> | **完整**（当前 input_v3/ 示例，25 排放 + 15 IC + 31 沉降…） | ✅ 可跑，O₃max = 103.0 ppb |
>
> 未列出的物种：IC → 0 · 排放 → 0 · BC → 无约束 · 沉降 → 0。
> **本表 111 行只是"可选项全集"**，不是启动条件。
> 级别说明：**✓ 推荐**（有物理意义、常用）· **△ 可行但需前提**（见备注）· **✗ 无物理意义**（别填）
>
> **技术前提**：`cfgbuild` 对 IC / BC / 排放 / 干沉 / 湿沉**都不设物种白名单**——
> 只要物种名在机制 `VARIABLE` 段（74 个）就能通过编译。本表给的是**物理合理性**判断，
> 而非程序能力边界。填了 ✗ 项不会报错，但会得到无意义的结果（如给 O¹D 设排放）。
>
> 数据来源：`mechanism/mechanism_3_full_chain.fac` 的 `VARIABLE` + `FORMULA` 段
> （程序化提取，74/74 全覆盖，无遗漏无重复）。

## 0. 五个输入通道速览

| 通道 | 文件 | 语法 | 物理含义 |
|---|---|---|---|
| **IC** 初始浓度 | `initialConcentrations.config` | `物种 值 [单位]` | 模拟起点浓度（前 1–2 天为建立期） |
| **BC** 边界/观测约束 | `bc.config` | `物种 = 值` 或 `= file:...` | 以 1/TAU_MIX 速率向该值/序列张弛（nudging） |
| **EMIS** 排放 | `emissions.config` | `物种 基线 BOX\|FLAT 振幅` | 物理账①：箱体单位体积排放率 |
| **DRY** 干沉降 | `drydep.config` | `物种 vd on/off` | k = vd/BLH |
| **WET** 湿沉降 | `wetdep.config` | `物种 a b` | Λ = a·RAIN^b |

## 4. 各通道的"可输入物种"白名单（推荐级）

### 4.1 IC（初始浓度）—— 48 物种推荐

**推荐**：除 `O1D`、`O`（激发态，恒稳态）外的**全部 72 个**都能设；
`OH`/`HO2`/`RO2`/`RO` 等 24 个自由基属"可行但有前提"（仅加速收敛）。

**实践**：一般只设主量（NO/NO₂/O₃/CO/CH₄/HCHO/PAN/ISOP/SO₂/DMS 等），
其余留 0 由机制自行生成。

### 4.2 BC（观测约束）—— 32 物种推荐

**推荐（有观测手段）**：

| 观测来源 | 可约束物种 |
|---|---|
| 地面常规站（AQI） | O3 · NO2 · SO2 · CO（NO 为差值不接） |
| 地面 VOCs（PAMS/TO-15） | HCHO · CH3CHO · ISOP · MVK · MACR · TERP（集总需加权） |
| 卫星柱（S5P TROPOMI） | **HCHO** · **NO2** · SO2 · CO · CH4 · O3 |
| 有机硝酸盐（TD-CIMS） | PAN · MPAN · ISOPNIT · ISOPDNT · RONO2 · OLENIT · TERPNIT |
| 过氧化物（HPLC） | H2O2 · CH3OOH |
| 酸/卤素（IC 分析） | HNO3 · HCl · HBr · H2SO4 · MSA |
| 夜间储库（CRDS） | NO3 · N2O5 · HONO · PNA |

**✗ 不可约束（26 个）**：全部自由基（OH/HO2/12 个 RO2/4 个 RO）、
`O1D`、`O`、`NO3`、`SO3`、`Cl`/`ClO`/`Br`/`BrO`——寿命远短于张弛窗口，
强行约束会把真实化学"钉死"成观测值，得到虚假的 O₃。

### 4.3 EMIS（排放）—— 19 物种推荐

**推荐（有实际排放源）**：

| 源类型 | 物种 |
|---|---|
| 交通（燃烧） | **NO** · **NO2** · **CO** · HCHO · CH3CHO · **ALK** · **OLE** · **ARO1** · **ARO2** |
| 工业/溶剂 | **SO2** · KET · ALK · ARO1/ARO2 |
| 生物源 | **ISOP** · **TERP** · DMS |
| 长寿命背景 | **CH4** |
| 其他一次 | HONO（燃烧直排，机制无源项故△）· Cl/Br（海盐，△）· H2SO4/MSA（△）· PAN（工业，△） |

**✗ 不可排放（39 个）**：全部自由基、O₃/H₂O₂/HNO₃/NO₃/N₂O₅/PNA、全部二次产物
（氢过氧化物、有机硝酸盐、GLY/MGLY/MVK/MACR、TERPCHO、SO₃/ClONO₂/BrONO₂/HOCl/HOBr）——
它们是化学反应的**产物**，不是排放物。

### 4.4 DRY（干沉降）—— 46 物种推荐

**推荐**：所有可沉降物种（O₃ vd 0.8、HNO₃ 2.0、H₂SO₄ 2.0、HCHO 0.3、
H₂O₂ 1.0、SO₂ 0.3、卤素储库 0.5–1.0、氢过氧化物 0.3–0.5、PAN/有机硝酸盐 0.1–0.3）。

**✗ 不建议（24 个）**：自由基/激发态（寿命太短，来不及沉降）、
CH₄（vd≈0，实际忽略）、CO（极慢）、活性卤素原子。

**关键教训**：**新物种若化学上无汇，必须配干沉降**——否则无界累积（OLEOOH 曾如此）。

### 4.5 WET（湿沉降）—— 32 物种推荐

**推荐（高溶解度）**：HNO₃ · H₂O₂ · H₂SO₄ · MSA · HCl · HBr · HOCl · HOBr ·
SO₂ · HCHO · CH₃CHO · 氢过氧化物 · 有机硝酸盐 · PAN · N₂O₅ · PNA · GLY

**✗ 不建议（27 个）**：疏水有机物（ALK/OLE/ARO/KET/TERP/ISOP 等）、
自由基、CH₄/CO（溶解度极低）。

## 5. 常见组合示例

### 5.1 最小城市配置（当前示例）
```ini
# IC:    NO NO2 O3 H2O2 CO HCHO CH4 CH3CHO PAN ISOP (10–15 个主量)
# EMIS:  NO NO2 CO HCHO CH3CHO CH4 ISOP SO2 DMS ALK OLE ARO1 ARO2 KET TERP (15)
# BC:    O3 CO CH4 (常数) — 可选加 HCHO/NO2 站点序列
# DRY:   31 个物种（含 OLEOOH）
# WET:   6 个（HNO3 H2SO4 MSA SO2 ...）
```

```ini
# BC:  HCHO = file:constraints/sat_HCHO_surf.txt

# TAU_MIX = 21600  (HCHO 有局地化学 → 中等 τ)
```

```ini
# EMIS:  DMS (FLAT) + Cl/Br 前体（△，需谨慎）

# DRY:   HCl HBr HOCl HOBr ClONO2 BrONO2
```

## 6. 程序能力 vs 物理合理性的边界

| 问题 | 答案 |
|---|---|
| 填了 ✗ 的通道会报错吗？ | **不会**——cfgbuild 只查物种是否在 `VARIABLE` 段 |
| 那为什么还要区分？ | 填 ✗ 项得到**物理无意义**结果（如给 O¹D 设排放 → 立即被机制吃掉，白费算力） |
| 新增物种后怎么更新本表？ | 重新跑本表的生成脚本（`VARIABLE`+`FORMULA` 程序化提取，见 §0 数据来源） |
| 加物种时必须同步哪几处？ | **三张表**：`emissions.config`（若有源）· `drydep.config`（若无化学汇）· `build_groups()`（若参与情景缩放）；含氮还要进 `noy_add`；高浓度还要进 ATOL 调优表 |
